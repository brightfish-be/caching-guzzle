# Support Laravel 13 and PHP 8.3

## Request
make this package ready for LAravel 13 and PHP 8.3

## Analysis
The runtime code needs no changes; what was out of date is the tooling, CI and the declared support.
This is a `change`, not a bug.

Correction: the first check below installed only `illuminate/cache`, which does not pull in Guzzle,
so it missed a real blocker. A new Laravel 13 app gets Guzzle 8.3.1 (`laravel/framework` allows
`^7.8.2 || ^8.0`), while this package allowed only `^7.0`. `composer.json` now has `^7.0|^8.0`; that
fix reaches consumers only once it is released. The 5 tests also pass on Guzzle 8.3.1. No Laravel dependency exists: the package only needs a PSR-16 cache,
so Laravel support comes from `Illuminate\Cache\Repository` implementing that interface.

Checked on 2026-11-06 in a throwaway copy, on PHP 8.4.27 (not 8.3):

- `illuminate/contracts` v13 requires `php ^8.3` and `psr/simple-cache ^1.0 || ^2.0 || ^3.0`, so the
  current `^2|^3` constraint is compatible.
- `illuminate/cache` v13.40.0 installs alongside the package.
- `Client` with a real `Illuminate\Cache\Repository` (ArrayStore): second request served from cache,
  and `cache_ttl => -1` works.
- The 5 existing tests pass on PHPUnit 9.6.38, with no `src/` change needed.

What needs work:

- **php-cs-fixer** `^2.16` resolves to v2.19.3, which refuses to run above PHP 8.0. The config
  already uses the 3.x `PhpCsFixer\Config` API. The `format` script passes no `--config`, so it
  does not find `.php_cs.dist.php`.
- **PHPUnit** `^9.6` is old. `phpunit.xml` has attributes that PHPUnit 10 removed
  (`backupStaticAttributes`, `verbose`, `convert*ToExceptions`) and points at the 9.3 schema.
- **CI** tests PHP 7.4 to 8.2: never 8.3 or later, and the 7.4 job cannot satisfy `php ^8.0`. Also
  uses `actions/checkout@v2`, `git-auto-commit-action@v4` and the obsolete `--no-suggest` flag.
- **Docs**: the readme states no supported versions.
- **Test gap**: nothing tests against a real Laravel cache; `tests/Mocks/Cache.php` is the only
  store.

Open question (settle in `/fodo:plan`):

- Raise the minimum to `php ^8.3`, or only add 8.3 to what is tested? `^8.0` already allows 8.3 and
  Laravel 13 installs with it, so raising is not needed for compatibility. It does drop 8.0 to 8.2
  users, which means a major version (3.0.0). The upside is simpler tooling: `illuminate/cache ^13`
  as a dev dependency needs PHP 8.3, so keeping `^8.0` means a Laravel test that only runs on some
  CI jobs. Recommended: raise to `^8.3` and release 3.0.0, but only after the Guzzle fix has shipped
  as a 2.x release. The clients require `caching-guzzle ^2.0`, so they would not pick it up from 3.0.0.

Consumers pin Guzzle themselves, so this package's fix is not enough on its own: kinepolis-client
(`^7.8.2`), movix-client and park-client (`^7.9`), gofilex-client (`^7.5`, and `caching-guzzle ^1.2`).

Out of scope: a service provider, facade or config file. The package has none, and it does not need
one to work in Laravel 13.

## Impacted files
- `composer.json`: PHP constraint, PHPUnit and php-cs-fixer versions, `illuminate/cache` dev
  dependency, version, `format` script config
- `VERSION.md`: version bump, kept in step with `composer.json`
- `phpunit.xml`: migrate to the new PHPUnit config format
- `.github/workflows/run-tests.yml`: PHP matrix, current actions, drop `--no-suggest`
- `.github/workflows/php-cs-fixer.yml`: current actions
- `.php_cs.dist.php`: adjust only if php-cs-fixer 3 rejects a rule
- `readme.md`: state the supported PHP and Laravel versions
- `tests/Feature/LaravelCacheFeatureTest.php`: new test against a real Laravel cache repository

## Plan
1. Decide the PHP minimum (open question above).
2. Update `composer.json`: `php`, `phpunit/phpunit` to a current major that supports the minimum,
   `friendsofphp/php-cs-fixer` to `^3`, add `illuminate/cache` to `require-dev`, and pass
   `--config=.php_cs.dist.php` in the `format` script.
3. Migrate `phpunit.xml` with `vendor/bin/phpunit --migrate-configuration`; fix any test deprecations.
4. Run php-cs-fixer 3 and adjust `.php_cs.dist.php` if a rule was renamed.
5. Add a feature test using `Illuminate\Cache\Repository`: cache hit, `cache_anew`, `cache_ttl => 0`
   and `-1`.
6. Update CI: matrix of supported PHP versions including 8.3, lowest and stable dependencies,
   current action versions, no `--no-suggest`.
7. State the supported versions in the readme.
8. Bump the version with `/fodo:commit`: major if the minimum PHP rises.

## Acceptance criteria
- `composer update` and `composer update --prefer-lowest` succeed on PHP 8.3
- `composer test` passes on PHP 8.3 with no PHPUnit deprecation or config warnings
- A test runs the middleware against a real `illuminate/cache` ^13 repository
- CI runs against both Guzzle 7 and Guzzle 8
- A real Laravel 13 app can `composer require` the package without constraint conflicts
- `composer format` runs on PHP 8.3 and picks up `.php_cs.dist.php`
- CI includes PHP 8.3, and no job targets a PHP version that `composer.json` excludes
- The readme states the supported PHP and Laravel versions
